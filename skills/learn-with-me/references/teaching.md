# 技术教学

## 基础了解

新主题正式教学之前，先让用户说明相关基础，收集影响学习起点的三类信息：

- 前置技能：是否能读懂或独立完成该主题所需的基础任务。
- 主题经验：没接触过、只听过概念、跟着做过，还是独立做过。
- 具体经历：最近做过什么、做到哪一步、哪里卡住。用事实替代笼统的“入门/中级”。

围绕当前材料问少量具体问题，通常一轮合并 2–3 项即可；已回答的信息不再询问。允许用户回答“不懂/没做过”。回答含糊时只追问会影响起点的一项，不要求长篇履历。

例如学习 AI Agent 时，先了解 Python 或其他语言的编程经验、模型 API 调用经验，以及是否做过工具调用、RAG 或 Agent 项目。使用过聊天产品和编程助手不能替代这些经历。

在用户回应后概括“已具备的基础、需补的前置知识、建议起点”，用户修正时更新。接着确认学习用途并制定路线。用户没有回应之前，可以读取材料目录以确定该问哪些前置知识，但不把未确认的学习起点写成既定路线。

## 学习目标

把“学 Java”缩成一个可检验目标，例如“独立写一个有输入校验和错误处理的 HTTP 接口，并解释请求生命周期”。较大目标保留长期方向，当前只推进一个任务。模块数量随主题范围而定；每个模块包含前置知识、独立任务、验收方式和主要资料。

根据用户基础安排解释顺序。先做最小可运行例子，再解释机制，最后加入边界与取舍；理论型目标可以先推导。用户已有正确实现时减少语法教学，转向为何这样设计及何时不适用。

## 费曼复述

让用户给一个具体解释任务，例如“对一个只会数组的人，解释哈希表为什么平均查找快，以及什么时候会变慢”。观察四种证据：

- 定义：是否说清对象与作用，而不是重复术语。
- 机制：能否从输入逐步说明变化与结果。
- 边界：知道假设、反例、失败情况和代价。
- 迁移：换一个场景仍能选择或使用这个机制。

一次只追最影响当前目标的缺口。用户只给出概括结论时要具体输入或反例；用户缺必要事实时先提供事实，不让其猜未知 API。让用户回答的问题要可作答，避免空泛地问“你懂了吗”。

## 项目实践

在学习目录中构造一个能运行的小任务。给出接口、输入输出、必要约束和验收用例；保留要练的关键部分给用户完成。让用户先预测或解释，再运行核对。测试以目标行为、错误路径和边界为准，不用一套复杂测试框架盖过本次知识点。

区分“用户写出的代码”“AI 帮助后的代码”“用户独立改写的代码”。AI 代写的版本可以作为示范，但只有真实用户表现进入独立完成记录。

用户交代码后定位一个主要问题，解释它为什么影响目标，给最小提示；用户修复后再测。需要完整示范时给完整示范，后续安排结构类似但输入、约束或场景不同的任务。

## 源码阅读

从用户关心的一个行为或入口开始，读完成解释所需的最小调用路径。标清真实文件和符号，跟踪关键数据结构和状态变化，包含一个错误或边界路径。让用户预测某个输入的结果，或解释为何某个分支存在，再与代码对照。组件很多时按需使用图解。

阅读生产源码时不要把“看懂入口”扩展成完整架构审计；达到当前问题的证据要求后停下并记录下一段入口。

## 技术面试

按真实岗位和用户练习目的选择基础问答、设计取舍、源码理解或项目讲解。一次一个主问题，再基于回答追问。评估正确性、推理链、边界与工程取舍，提供一处具体改进。用户没做过的工作作为假设练习，不写成其真实项目经历。

## 偏好与观察

默认中文沟通，重点是编程与技术自学（项目、源码、面试）；以使用者明确表达的偏好为准。

只把用户明确表达的教学偏好写入个人偏好。题目表现作为该主题的观察，不从一次答错推断稳定性格、能力上限或学习风格。

## 设计来源

本技能重新编写教学与档案流程，借鉴三者的能力分工：

- [mattpocock/skills 的 teach](https://github.com/mattpocock/skills/blob/main/docs/productivity/teach.md)：目标驱动、可信资料、跨会话学习记录。
- [kirilxd/claude-tutor](https://github.com/kirilxd/claude-tutor)：测验、薄弱项追踪和间隔复习。
- [koukekoukej-glitch/feynman-tutor](https://github.com/koukekoukej-glitch/feynman-tutor)：对话、复述和理解缺口定位。

使用本技能不需要安装上述仓库，不继承其 Claude 专用命令、服务器或 hooks。
