# 并行备题

## 按依赖分工

独立题：在资料范围和适用基础确定后，题干、考查概念和评价要点不依赖学习者未来回答。例如围绕已选小节准备输出预测、独立实现和机制解释题。提前准备少量候选题，通常 2–4 题足以覆盖近期任务，不预生成全书题库。

依赖回答的题：追问用户的具体论证、针对其代码的排错、纠正已暴露的误解、根据表现升降难度，以及由已完成题目决定的迁移检验。先等待真实回应，再生成题干与反馈；可以事先设计分支方向，但不假设分支已经发生。

基础还未确认时，可根据已读材料预备不同基础适用的候选题，不选定其为正式学习起点。基础回答、目标或资料变化后重新筛选，保持“先了解基础再教学”。

## 执行方式

当前环境支持子 agent 且并行准备有收益时，把相互独立的资料阅读或备题任务交给备题 agent。主 agent 负责基础了解、学习对话、反馈与档案写入；备题 agent 只返回候选题，不自行与用户对话或修改学习档案。

任务说明包含已读来源/需要核对的具体小节、已确认基础、当前目标、要准备的概念、题量与题型，以及已有题目以便去重。基础未知时明确写“未知”，要求标注每道题的适用前置知识。返回题干、评价要点、可核对出处和适用条件；不返回虚构的用户回答、分数或掌握状态。

资料读取和题目任务真正独立时并行执行；依赖材料结论或用户回答的任务按顺序执行。优先让当前问题尽快送达用户，之后在有可持续异步执行能力的环境中让备题任务继续。没有这种能力时，在当前活动回合批量备题并保存，下一回合复用；结束回合后不声称自己仍在后台备题，也不以睡眠轮询模拟并行。

不具备子 agent 能力或任务很小时，由主 agent 一次批量准备同等规模候选题。实际未运行并行任务时只说“提前备题”。采用当前环境可用的能力，不依赖某一产品专用的工具名。

## 备题缓存

启用持久化时，将通过来源与题意核对的题目增量写入当前主题的 `QUESTION-BANK.md`；用户要求不保存时留在本次上下文。每个条目使用稳定 ID，包含：

- 题干与题型、考查概念、适用前置知识与难度。
- 来源链接/代码位置，版本或查阅日期。
- 所依据的目标与学习范围，以及评价要点。
- 状态：候选、已展示、已回答或失效。

评价要点用于核对答案，默认不把题库文件作为课件打开，也不在展示题目时泄漏后续题解。用户明确要参考答案时提供，并按实际帮助程度记录学习证据。

候选题不是学习证据，只有用户真实回答后才评分、写进度和安排复习。主 agent 独占备题缓存和学习档案的写入，避免并行任务覆盖同一文件。

## 回答到达后的调度

1. 先处理并评价当前真实回答；有关键缺口时生成针对性追问或修补任务，不机械推进候选题。
2. 没有阻塞缺口时，从缓存选择符合最新基础、目标、难度和当前单元的下一题。未展示前检查它是否重复、是否被前一题反馈泄漏答案、是否需要尚未具备的前置知识；不适用的题重新生成或标为失效。
3. 默认只展示当前一题。学习者明确要求批量作答时，再成组展示相互独立且适用的题。
4. 候选题不足时补充近期题目；缓存已够用时不扩充。用户改目标、明确暂停或取消时，停止无关备题任务，保留真实学习记录。

例如读 AI Agent 书时，组件分工和某段已读伪代码的行为可以提前备题；“你为什么把工具执行归给模型”这样的追问，必须在用户确实给出对应回答之后生成。
